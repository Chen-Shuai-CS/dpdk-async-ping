# 是哪一处改动让段①的慢发送变多了（2026-10-02）

v4 的第一版（提交 `1da94bf`，标签 `v4-first`）在把"回复的身份核对"提前到接收时的同时，删掉了 sleep 之后的那次核对。
同场对比发现 A、B 的慢发送占比都升高了。这里是把原因钉死的那一轮：五个版本的 A、B 轮流各跑 20 秒 × 3 轮。

| 文件名里的记号 | 是什么 | 怎么得到 |
|---|---|---|
| `v3` | 上一个版本 | 标签 `v3` |
| `m1r2` | v3 + 最小的改动：接收时多比较一次时间戳（R1）+ 发送重试检查停止标志（R2），其余一行不动 | `git checkout v3 && git apply minimal.diff` |
| `m2` | `m1r2` 再去掉 sleep 之后的那次核对 | `git checkout v3 && git apply minimal-without-second-check.diff` |
| `v4` | v4 的第一版 | 标签 `v4-first` |
| `vb` | v4 的第一版的结构（A、B 共用 `judge`）+ 保留 sleep 之后的那次核对 = **最终的 v4** | 标签 `v4` |

结论见 `docs/REPORT.md` §3.4：去掉那次核对（`m2`、`v4`）之后慢发送变多，保留它（`m1r2`、`vb`）则与 v3 相同。
